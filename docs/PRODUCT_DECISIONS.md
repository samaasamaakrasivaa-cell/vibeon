# Реестр продуктовых решений

Архитектура команды утверждена. Правило меняется после решения владельца продукта и проверки затронутых команд.

## RELEASE-AUTH-01

Владелец продукта, 27.11.2026. Однозначно поставленная и согласованная продуктовая задача включает реализацию, применимые проверки, интеграцию через PR и обычный выпуск в пределах задачи. Tech Lead доводит работу до проверенного результата на сайте; техническое переключение выполняет существующий GitHub CI через уже подключённый сервер. Повторное согласие владельца на конкретный SHA, merge или обычную публикацию не требуется. PM фиксирует фактический статус в дашборде. [Решение владельца](https://github.com/samaasamaakrasivaa-cell/vibeon/issues/8#issuecomment-7216967478) · [Процедура выпуска](RELEASE_RUNBOOK.md#допуск-к-выпуску)

В CD-01 владелец дополнительно поручил восстановить самостоятельную выкладку, ранее выполнявшуюся через Server. Согласовано использовать существующие GitHub Actions и SSH-подключение без новых платных сервисов, API-ключей или расширения доступов. Исполнитель выпуска — проверенный workflow; ожидание отдельного неопределённого оператора не завершает задачу. Если реальное ограничение доступа или неуспешная проверка мешает выпуску, агент сообщает конкретную причину и устраняет доступную ему часть самостоятельно.

Отдельно согласуются новые продуктовые решения, расширение границ задачи, изменение прав, новые доступы и расходы, необратимые операции, массовый пересчёт истории и действия с риском потери данных. Ранее установленные ограничения по миграциям, чувствительным данным и отдельным задачам сохраняются. Источник полномочий должен подтверждать решение владельца. Произвольный публичный комментарий такого подтверждения не даёт.

Для Placement требуется отдельное решение перед пересчётом исторических попыток, изменением опубликованных результатов или отчётов и изменением связанных Checkpoint.

## TEAM-INTAKE-01

Владелец VibeOn, 27.11.2026. Большой пакет принимает IT Project Manager, короткая однозначная задача может поступить прямо профильному агенту. У задачи одна карточка и один подтверждённый исполнитель. Для продуктовой задачи результат подтверждается на сайте по RELEASE-AUTH-01. Tech Lead сопровождает допуск и восстанавливает незавершённые прямые поручения. PM читает статусы из общей карточки. Действующая автоматическая очередь сохраняет свои полномочия. Решение относится ко всем ролям. [Постановка №55](https://github.com/samaasamaakrasivaa-cell/vibeon/issues/55) · [Порядок работы](DEVELOPMENT_RULES.md#приём-и-возобновление-задач)

## OWNER-RELEASE-NOTES-01

Поручение владельца передано 27.11.2026. После каждого подтверждённого пользовательского результата подготовь короткое описание на русском языке. Исполнитель сохраняет заметку в существующей карточке или связанном PR, Tech Lead подтверждает факт публикации, PM включает ту же заметку в сводку. Решение охватывает оба способа постановки и все модули. [Поручение](https://github.com/samaasamaakrasivaa-cell/vibeon/issues/8#issuecomment-7225144987) · [Формат заметки](DEVELOPMENT_RULES.md#заметка-для-владельца)

## Открытые продуктовые вопросы

| Вопрос | Предложение для обсуждения | Участники |
|---|---|---|
| Что доступно после истечения подписки | Льготный период, затем доступ к истории и продлению | Finance, Platform, Teacher |
| Блокировка преподавателя и доступ его учеников | Отзыв прав преподавателя с сохранением разрешённой ученику ранее опубликованной истории | Platform, Finance, Teacher, Student |
| Подтверждение оплаты | Сверка преподавателем, OCR помогает извлечь сумму | Finance, AI |
| Изменение использованного задания | Архив и новая версия для будущих назначений с сохранением существующих ответов | Builder, Classroom, Homework |
| Повторное назначение Placement | Сохранить историю начатой попытки и отдельно определить видимость прежнего результата | Placement, Roadmap |
| Сроки хранения, удаление и передача данных | Утвердить категории, сроки, получателей, основания и обработку данных несовершеннолетних с отдельной юридической проверкой | Platform, AI и владельцы предметных данных |
| Допустимая потеря данных и срок восстановления | Согласовать цели и проверить их фактическую достижимость по процедуре выпуска | Platform, Tech Lead |

В принятом решении запиши дату, правило, владельца, затронутые модули и ссылку на согласование. Инструкции по работе с текущей системой находятся в [архитектуре](Архитектура_и_стек.md) и [карте модулей](MODULES.md).
