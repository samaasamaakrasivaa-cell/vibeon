# PT-12. Запись подтверждённого результата для Roadmap

[Решение в №37](https://github.com/samaasamaakrasivaa-cell/vibeon/issues/37#issuecomment-7240105154) · [Формат читателя №105](https://github.com/samaasamaakrasivaa-cell/vibeon/blob/1f193a5cac39875917e3794a4e522c1d2c63dd89/docs/placement/PT-05-roadmap-proposal.md#вход-placement)

Внутренний [модуль записи](../../src/lib/placement/roadmap-result.ts) готовит команду по проверенным на сервере фактам. Только владелец назначенной попытки в статусе `submitted` или `reviewed` может сохранить полный снимок в `review.roadmapResultV1`. При записи сервер заново получает факты и сверяет текущую версию ответов и предыдущую версию результата. Повтор команды возвращает уже сохранённый снимок и время. При конкурентной правке сервер перечитывает запись. Устаревшая команда не записывается.

Writing и Speaking получают уровень по Cambridge-рубрике только для действующего подтверждения преподавателя, привязанного к актуальному ответу. Для Speaking вызывающий серверный код дополнительно проверяет происхождение каждого использованного аудио и передаёт отпечаток этой версии. Снимок допускает только перечисленные в контракте поля. Черновики ИИ, расшифровки и тексты ответов в снимок не копируются. Отсутствующая запись, неподтверждённый результат и неизвестный источник представлены отдельными причинами.

После серверных подтверждений №32 и явного утверждения уровня №36 подключить запись к отдельному действию №36. Сервер получает преподавателя из сессии, пересчитывает выбранные факты из актуальной попытки и передаёт их модулю записи. Уровень и факты должны пройти проверку до записи снимка. Нынешняя финализация отдельно обновляет Checkpoint и ученика. Для записи снимка она не используется. Формирование, отправка отчёта, повтор блока и признак очереди №37 остаются отдельными действиями. Миграция схемы для этого JSON-ключа не нужна.

## Воспроизведение

Применить текущие миграции на отдельной PostgreSQL 16 с БД `pt_roadmap_writer_fixture` по адресу `127.0.0.1`. Скрипт отклоняет другой адрес или имя БД.

```sh
node --conditions=react-server --import tsx scripts/check-placement-roadmap-result.ts
```

Для проверки совместимости можно указать `ROADMAP_CONTRACT_MODULE` с абсолютным путём к `src/lib/roadmap/placement-proposal.ts` из отдельной копии на SHA читателя `1f193a5cac39875917e3794a4e522c1d2c63dd89`. В тесте серверные подтверждения и подтверждение уровня заданы синтетическими данными. Используется настоящая запись с повторным чтением PostgreSQL. Проверяется первая запись, два одновременных повтора, сохранность времени, отказ после замены аудио или уровня, сохранность отчёта и его параллельного черновика, маршрута, ученика, прогресса и Checkpoint.
