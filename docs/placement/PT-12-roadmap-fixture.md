# PT-12. Проверка передачи подтверждённой диагностики в Roadmap

Один синтетический пример для [№37](https://github.com/samaasamaakrasivaa-cell/vibeon/issues/37) и [№35](https://github.com/samaasamaakrasivaa-cell/vibeon/issues/35). Тестовый сайт запускается на [ревизии читателя PR №105](https://github.com/samaasamaakrasivaa-cell/vibeon/tree/1f193a5cac39875917e3794a4e522c1d2c63dd89). Сценарий создаёт `review.roadmapResultV1` только в изолированной фикстуре. Код штатного подтверждения результата остаётся отдельным этапом.

| Поле | Значение |
|---|---|
| Попытка | `pt37-roadmap-fixture` |
| Версия результата | `pt37-roadmap-fixture-v1` |
| Подтверждение (UTC) | `2026-11-28T10:00:00.000Z` |
| Итоговый уровень | B1 |
| Second conditional | 1/4, пробел. Исходные ответы `conditional-1`–`conditional-4`. |
| Past perfect | 3/3, уверенное выполнение. Исходные ответы `past-1`–`past-3`. |
| Грамматика | B1. Источник — исходный блок `state.core` в сохранённой попытке. |
| Отсутствующие данные | Артикли, письмо и лексика не проверены. Чтение и говорение не подтверждены. Источник аудирования неизвестен. |

На сайте преподаватель открывает вкладку Roadmap у синтетического ученика. Предложение ссылается на попытку, выводит B1 и дату, объясняет перемещение Second conditional и показывает пробелы в данных. Затем преподаватель открывает отчёт, меняет язык черновика, формирует PDF и отдельно отправляет отчёт. После назначения и сдачи повторного чтения ученик открывает прежнюю публикацию. Тест сравнивает целиком подтверждённый результат, маршрут, строки обычных уроков и их прогресса, уровень ученика и обе контрольные точки после каждого шага. Повторный текст выбирает штатный банк.

## Воспроизведение

1. Открой отдельную копию репозитория на `1f193a5cac39875917e3794a4e522c1d2c63dd89` и выполни `npm ci`. Подними пустую PostgreSQL 16 на loopback. Назови БД `pt_roadmap_fixture`. Синтетический сценарий завершится ошибкой при повторном запуске в той же непустой БД. Для повторения используй новый одноразовый экземпляр.
2. Из копии читателя при установленном `DATABASE_URL` запусти `node_modules/.bin/prisma migrate deploy`. Запусти приложение в среде без рабочих ключей, с `BILLING_SCHEDULER=off`, `APP_URL=http://127.0.0.1:3083` и командой `npm run dev -- -H 127.0.0.1 -p 3083`.
3. Скопируй [скрипт проверки](../../scripts/check-placement-roadmap-handoff.cjs) в отдельную папку. Из копии читателя запусти следующую команду. `PLAYWRIGHT_CORE` — абсолютный путь к установленному пакету `playwright-core`. `CHROMIUM_EXECUTABLE` можно указать при отличающемся пути к Chromium.

```sh
PLAYWRIGHT_CORE=/path/to/playwright-core \
  TEST_SITE=http://127.0.0.1:3083 RESULT_JSON=/tmp/pt37-roadmap-result.json \
  node --conditions=react-server --import tsx /path/to/check-placement-roadmap-handoff.cjs
```

`RESULT_JSON` содержит фактический снимок, ID созданного Checkpoint, маршруты тестовых страниц и отдельную версию опубликованного отчёта. Прогон проверяет действующие пути просмотра, подготовки PDF, отправки и сдачи повторного блока. Отдельный признак успешной генерации для очереди №37 и штатную запись нового подтверждённого результата этот сценарий пока проверить не может.
