# PT-08. Черновик ИИ и подтверждение преподавателя

[Задача №32](https://github.com/samaasamaakrasivaa-cell/vibeon/issues/32)

Контракт [ws-assessment.ts](../../src/lib/placement/ws-assessment.ts) описывает отдельный ключ `PlacementAttempt.review.wsAssessment` со схемой 1. В кабинете преподавателя [компонент просмотра](../../src/components/placement/WsAssessmentStatus.tsx) читает этот ключ отдельно для Writing и Speaking. Попытки без сохранённого состояния нового формата отображаются в прежнем виде. Существующие действия оценивания и чтение ученических отчётов используют прежние поля.

- Writing и Speaking хранят черновик ИИ, состояние запроса и подтверждение независимо. Черновик использует результат существующей проверки ИИ. Подтверждение хранит баллы по всем критериям, автора, дату и необязательные комментарии. Для пустого ответа или отсутствующей записи новый запрос ИИ и подтверждение недоступны.
- Версия блока учитывает снимок задания, текст ответа или ссылки на записи по номерам вопросов и рубрику. В ключе версии хранится отпечаток. При смене версии подтверждение остаётся в истории и становится неприменимым к текущему ответу. При явном переоткрытии преподавателем подтверждение также архивируется. Блок получает новую ревизию, а черновик той же версии ответа остаётся доступен.
- Каждый принятый запрос ИИ получает следующий номер внутри ревизии блока. Результат или ошибка должны совпадать с номером и ID ожидающего запроса текущей ревизии. При повторном использовании ID старый результат и старая ошибка игнорируются. Подтверждение преподавателя прекращает ожидание ответа ИИ. Ошибка текущего запроса оставляет предыдущий черновик доступным.
- Старые баллы, опубликованные снимки, итоговый уровень и данные Checkpoint/Roadmap остаются в своих полях. Историческая оценка читается прежним способом. Контракт не объявляет её новым подтверждением.

До подключения серверных действий согласовать с AI & Quality права на подтверждение и переоткрытие, а также пустые ответы. При сохранении новой версии ответа обновлять ревизию соответствующего блока вместе с этой версией. Перед записью заново читать попытку и вычислять источник по актуальному состоянию. При старте сверять номер предыдущего запроса и передавать ревизию, ID и присвоенный номер в обработчик результата или ошибки только после успешного сохранения. При конкурентном изменении применять тот же переход к свежей записи, чтобы сохранить второй блок. Проверить совместимого читателя и откат до включения записи. Формат для №28 и отправку итогового отчёта в этом этапе не подключаем.

Проверка на синтетике без БД и внешних вызовов

```sh
node --conditions=react-server --import tsx scripts/check-placement-ws-assessment.ts
```

## Изолированная запись решения преподавателя

В режиме `PL_WS_TEACHER_WRITE=1` у каждого завершённого блока есть своя форма оценки. Преподаватель заполняет критерии и явно нажимает «Подтвердить оценку». Для редактирования действующего решения он сначала переоткрывает этот блок. Команда сверяет владельца, последнюю сдачу, состояние попытки, рубрику и версию ответа. Для Speaking проверяется наличие всех указанных файлов текущего задания. Оцениванию может хватить части записей, если преподаватель может заполнить все критерии. Запись меняет только `review.wsAssessment`. Старые оценки, отчёты и данные маршрута остаются доступными.

Переменная по умолчанию выключена. Этот этап позволяет независимо проверить ручное решение и переоткрытие. Новый черновик Speaking, проверка серверного происхождения записей и расшифровок, согласование включения входят в следующие шаги №32. Ручной режим на синтетике использует существующие черновики. История и описание черновика видны рядом с формой на экране из №102.

Для серверной проверки нужны запущенная на `127.0.0.1` отдельная PostgreSQL с применёнными миграциями и именем БД `pt_ws_teacher_fixture`, а также новый каталог файлов.

```sh
UPLOAD_DIR="$(mktemp -d /tmp/vibeon-pt08-fixture-XXXXXX)" \
  node --conditions=react-server --import tsx scripts/check-placement-ws-teacher-write.ts
```

В изолированном режиме новая версия ответа Writing или файла Speaking архивирует прежнее подтверждение в той же записи. Загрузка Speaking повторно проверяет статус, задание и версию записи выбранного вопроса. Две загрузки разных вопросов сохраняются независимо. Для дополнительной HTTP-проверки укажите `WS_TEACHER_FIXTURE_ORIGIN` на локальный экземпляр с флагом и той же синтетической БД.

Для Writing запрос ИИ сначала выделяет номер запуска в текущей версии ответа. Поздний результат после учительского подтверждения отклоняется, сбой оставляет доступным ручное решение. Черновик сохраняется отдельно. При включённом тестовом режиме прежняя команда ИИ и автосохранение прежних баллов Writing/Speaking отключены на сервере.
