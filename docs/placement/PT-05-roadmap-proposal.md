# PT-05. Предложение по учебному маршруту

Учитель открывает ученика → «Маршрут к цели». Над текущим маршрутом видно предложение по порядку будущих тем, сопоставление «Сейчас» и «Предлагается», результат диагностики и пробелы в данных. До подтверждения предпросмотр работает только на чтение. Для утверждённого маршрута автоматический запуск прежнего разбора ИИ при открытии вкладки отключён. Ручная команда разбора доступна.

Порядок меняется только внутри будущего этапа. Пробелы идут раньше зон роста, те — раньше уверенно выполненных тем. Незнакомые идентификаторы и точки с неполным подтверждением остаются на своих местах. Оценка диагностики сама по себе не выставляет отметку об освоении. Сопоставление выполняется по идентификаторам справочника грамматики и его явным псевдонимам. Неоднозначные идентификаторы, этапы с зафиксированной работой и участки вплоть до существующего среза защищены от правки. Начатые уроки учитываются при определении защищённой части маршрута.

Сервер заново проверяет владельца маршрута, версию фактов, утверждение, прогресс, Checkpoint и порядок тем в момент подтверждения. Меняется порядок уже существующих точек, без новых строк маршрута и без записи в Placement, Checkpoint или журнал уроков. При повторе того же подтверждения сервер распознаёт уже применённый порядок. Если версия диагностики или существенные данные маршрута изменились, учитель видит обновлённое предложение.

## Вход Placement

Roadmap читает подготовленный Placement снимок из `PlacementAttempt.review.roadmapResultV1` для той же пары ученик / преподаватель и попытки в режиме `student`. Ключ — предлагаемая точка интеграции №35, отдельная от очереди и опубликованного отчёта. Версия присваивается Placement при явном подтверждении диагностических фактов. При смене версии снимок заменяется целиком. Поля проверяются схемой `confirmedPlacementSchema`.

| Поле | Ожидание Roadmap |
|---|---|
| `attemptId`, `version`, `confirmedAt` | ID текущей попытки, стабильный ID версии и время подтверждения в ISO UTC. |
| `level` | Подтверждённый общий уровень CEFR. |
| `topics[]` | Идентификатор темы. У проверенной темы есть `status: checked`, итог `gap / partial / secure`, `correct / total` и источник. |
| `skills[]` | Идентификатор навыка. У проверенного навыка есть `status: checked`, подтверждённый уровень и источник. |
| `provenance` | Для каждого проверенного факта есть `scope` (`initial / additional / reassessment / teacher-adjustment`) и `evidenceId` записи с известным происхождением. |
| `status: unknown` | Явное отсутствие данных с причиной `not-tested / not-confirmed / unknown-origin`. Без оценки, вердикта и источника. |

Сохранение или формирование отчёта, выдача и сдача повторного раздела оставляют подтверждённый снимок прежним. Кандидаты переоценки №33, смешанные результаты без установленного происхождения №34 и черновой зачёт №40 в подтверждённый снимок не входят. Версия опубликованного отчёта PT-11B сама по себе не содержит этого контракта. Для действующих попыток запись ключа должна появиться в Placement после проверки стыка №37.

## Воспроизведение

```sh
node_modules/.bin/tsx scripts/check-roadmap-placement-proposal.ts
```

Синтетический пример использует утверждённый маршрут с текущим срезом. В будущем этапе «Условные предложения второго типа» предлагается поднять с третьей позиции на первую после 1 верного ответа из 4. «Артикли» остаются на своей позиции из-за отсутствия данных. Сохранение маршрута проверяется отдельно от состояния очереди и отчёта Placement.
